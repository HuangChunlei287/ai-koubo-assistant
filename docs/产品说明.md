# AI 口播创作助手 · 产品说明（一页版）

## 一句话定位

帮中文短视频创作者把「一个主题」快速变成「能直接拍的口播脚本 + 分镜 + 字幕重点词 + 发布文案」。

## 访谈发现的痛点（3 名创作者，2026-11-25）

访谈对象：U1 小吃街探店（抖音）、U2 文创店探店（小红书）、U3 散步随拍（抖音）。完整记录见 `docs/访谈记录.md`。

三个人都绕不开「把想法变成能说出口的话」，但卡点不同：

- **U1**：最耗时是描述味道，最纠结开头，怕太普通被划走；最想要**脚本**。
- **U2**：最耗时是删减内容/取舍，最纠结中间亮点；录的时候容易啰嗦，最想要**重点词**。
- **U3**：不写完整稿，最烦状态和冷场；完全不规划镜头，最想要**分镜**。

共同问题：脚本开头难写、内容取舍耗时、拍摄时忘词/卡壳、画面单调。

典型流程：想主题 → 备忘录/搜索资料 → 写稿或记关键词 → 现场拍 → 配字幕/发布。步骤分散，准备时间长。

本产品把这条链路收进一个页面：先给主题，AI 出脚本；人改脚本；AI 拆分镜；再出重点词和发布文案。

## 目标用户

- 主要：有 1–10 万粉的探店 / 种草 / 知识分享类口播创作者，通常自己写、自己拍
- 次要：门店商家、运营岗，需要快速产出到店口播视频
- 非目标：专业影视团队、需要 AI 直接生成成片的用户

## 核心流程

```
输入创作需求（主题/平台/受众/时长/风格）
        ↓
AI 生成口播脚本（钩子 + 正文 + 行动引导）
        ↓
用户编辑脚本
        ↓
AI 拆解拍摄分镜（镜头/时长/画面/构图/氛围/台词/字幕/重点词/拍摄提示）
        ↓
生成发布文案（标题/封面短句/平台描述）
        ↓
复制分镜和文案，进入拍摄
```

## MVP 范围

必须做：

- 创作需求输入
- 口播脚本生成，可编辑、可重新生成
- 分镜拆解，结果可查看、复制
- 字幕重点词
- 异常提示（缺 Key、网络失败、模型返回异常）

暂不做：

- 真实视频剪辑 / 数字人 / 自动配音
- 素材库、模板库
- 一键发布到抖音/小红书
- 多用户、账号体系、云端同步

## 功能优先级

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | 主题 → 口播脚本 | 解决「不知道写什么」的起点问题 |
| P0 | 脚本 → 拍摄分镜 | 把文案变成可执行的拍摄清单 |
| P0 | 异常处理与重试 | 模型接口不稳定时不能白屏 |
| P1 | 字幕重点词 | 直接影响成片可看性，成本低 |
| P1 | 发布文案 | 减少发布前的重复劳动 |
| P2 | 会话历史 / 复制 | 方便复用和交给拍摄者 |
| P3 | 多平台语气差异 | 先观察用户是否真的需要 |

## 成功指标（Demo 阶段）

- 从输入主题到拿到可编辑脚本：< 60 秒
- 从脚本到分镜：< 90 秒
- 分镜中台词与脚本一致率：100%（服务端逐字校验）
- 3 名体验用户中，至少 2 人能在不看说明的情况下完成完整流程
- 至少 1 条真实反馈被采纳并形成一轮修改记录

## 关键假设与验证情况（2026-11-25）

1. 创作者最大的时间消耗在脚本/分镜准备，而不是剪辑 —— **部分验证**：3 人都卡在准备阶段，但具体卡点不同（U1 脚本、U2 取舍、U3 分镜）。
2. AI 生成的脚本需要可编辑 —— **验证**：U1/U2 都会自己改稿，不会直接照念。
3. 分镜的「画面建议」比专业运镜术语更有用 —— **验证**：U3 只需要知道什么时候换角度、切什么画面。
4. 用户愿意为「省时间」付费 —— **未验证**：访谈没有问付费，需后续测试。

## 风险

- 模型输出不稳定：已加服务端字段规范化，但仍需测试用例覆盖
- 生成内容同质化：需要通过风格、平台、受众输入拉开差异
- 用户不信任 AI 写的卖点：脚本必须可编辑，且不编造事实
- 真实需求可能与假设不符：先访谈，再决定是否加功能

## 访谈对产品的启示

- **入口分模式**：没脚本 → 生成脚本；有脚本 → 拆分镜；只想要提醒 → 重点词/提词器。
- **脚本必须可编辑**：U1/U2 都会自己改稿，不会直接照念 AI 文案。
- **重点词要短、能扫一眼**：不是长句总结，而是价格、卖点、行动词。
- **分镜建议要说人话**：U3 不需要专业运镜术语，只需要「什么时候换角度、切什么画面」。
- **设备假设要保守**：三个人都是单人、手机拍摄，不应默认有团队、灯光、稳定器。
